I am starting to make executables for the machines. This includes the teknic motors,
bath, temperature controller, and labjack. The binaries are written to the
    Mathematica-C-Integration\c++\Local\bin folder but I am copying and pasting them to the
    Mathematica-C-Integration\binaries folder which is the official folder for them and has less clutter.

The important inputs are sent through the command line and received in the code with:

    int main(int argc, char** argv)

This way we can pass values from Mathematica to the executables.
An example command is:
    bath_set_temp.exe COM5 27.0
This sends the command to set bath temperature on COM5.

The outputs are sent through stdout so they can be read back into Mathematica.

So far, the return values are opposite of convention, with 0 (false) meaning unsuccessful and 1 (true) meaning success. We may want to change this.
So far, the binaries only need sFoundation20.dll to be in the same folder (to work with the motors). The bath, temp controller, labjack will work on their own.





Building these executables:

I wrote classes for the neslab bath and the temperature controller which means that vscode is not auto configured to build executables for these appliances
I have been compiling from the command line by copying and pasting the command generated by the vscode run button and adding the necessary class file names ("RTE7.cpp" or "OVEN5R6900.cpp") to the command.
A sample command looks like this:
    cmd /c chcp 65001>nul && cmd /c "call "C:\Users\Student\Documents\Summer 2025\Mathematica-C-Integration\c++\Local\.vscode\init_teknic_env.cmd" && cl.exe /Zi /EHsc /nologo /Fe"C:\Users\Student\Documents\Summer 2025\Mathematica-C-Integration\c++\Local\bin\bath_get_temp.exe" "C:\Users\Student\Documents\Summer 2025\Mathematica-C-Integration\c++\Local\bath_get_temp.cpp" RTE7.cpp sFoundation20.lib"

The "RTE7.cpp" is inserted near the end.
